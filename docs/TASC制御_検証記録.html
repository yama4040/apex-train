TASC制御の導入検証

要約

TASCは機能した。しかし学習ループには入れられなかった

停止位置制御そのものは設計どおり動き、どんな方策でも±20cm以内に停止させられることを確認した。問題は「TASCをDQNの学習ループに組み込む」ことにあり、報酬の与え方を4通り試したがすべて別々の形で破綻した。最終的にTASCを学習から外し、運転曲線の後処理として適用する構成に落ち着いた。

最終構成

学習ループ：TASCは一切介入しない（TASC_ENABLED = False）。観測は30次元に復帰し、学習の力学はTASC導入前の実績ある状態に戻した。

後処理：apply_tasc_to_runcurve.py が走行ログの停止部分だけをTASCの制動パターンで上書きする。実車と同じく「停止位置制御はTASCが担う」という役割分担を、運転曲線上で色分けして明示する。

検証 01

TASC単体は±20cmを達成できる

まず制動パターンを、停止点から実際の勾配・走行抵抗で逆積分して構築した（物理モデルは train.py と同一）。制限速度70km/hからの制動開始距離は 228.5m。ここから、精度を決める要素を3つ切り分けた。

停止精度を決める3要素（進入速度30〜70km/hでの最大誤差）
制御方式最大誤差所見
パターンに当たったら制動一択−6.7 m勾配で止まりすぎる。追従制御が必須
パターン追従（0.1秒判定・先読みなし）1.42 m作動判定が1ステップ遅れる
＋作動判定の先読み0.98 m—
＋作動後は0.01秒周期で追従0.042 m±20cmを達成

作動判定の遅れは回復できない。制動は最大減速なので、1ステップ(0.1秒)遅れると最大1.4m行き過ぎてしまう。そのため判定時に「次ステップで進む距離」を先読みする必要がある。

停止の保証は「学習」ではなく「上書き」から来る

どのような方策でも停止できるかを、極端なエージェントで確かめた。

方策非依存性の検証
エージェント停止誤差

TASCは毎ステップ監視して条件成立時に行動を上書きするため、学習が未収束でもオーバーランは起こらない。この性質は最後まで揺るがなかった。

検証 02

4回の試行と、それぞれの破綻

TASCを学習ループに入れると、TASC作動中の区間をどう評価するかという問題が生じる。負・正・中立・終了と4通り試したが、すべて別の形で失敗した。

試行 01

LLM評価をそのまま使う 崩壊

TASC区間の評価＝報酬NNの出力のまま

報酬NNは駅接近時の連続制動を0.0近くと評価した。そのためTASC制動とクリープ走行（ちんたら運転）が報酬でほとんど区別できず、エージェントは早期減速して這う挙動に落ち込んだ。

TASC制動 llm 0.023 → −0.477/秒　　クリープ llm 0.0 → −0.500/秒　　差わずか0.023
試行 02

満点1.0を与える 搾取

TASC区間の評価＝常に 1.0

クリープとの区別はついたが、今度はTASC区間が長いほど得になった。速く突っ込むほど制動時間が延びるため、巡航では0点を取り続けながらTASC区間で稼ぐ挙動が現れた。

70km/h巡航で llm 0.00（−0.5/秒）を続けつつ、TASC区間163歩で +12.7 を獲得
試行 03

中立0にして、作動時にエピソード終了 Q値発散

TASC区間の評価＝0.5（報酬0）＋ 作動で done

制御していない区間を学習から外す狙いだったが、エピソードが駅に到達しなくなった。「作動を避ければエピソードが続く」構造になり、クリープが終了回避の手段になった。

819歩まで伸長（正常は約320歩）　　maxQ 165,467（本来の上限は約200）
試行 04

中立0のまま、終了は廃止 ジグザグ

TASC区間の評価＝0.5（報酬0）／エピソードは駅到達で終了

エピソードは正常に終わるようになったが、Q値の膨張は止まらなかった。3つの行動のQ値がほぼ同一になり、argmaxがネットワークの近似誤差で入れ替わって、1〜4秒周期の力行⇔ブレーキが発生した。

Q値 平均340.7 に対し 1位と2位の差 平均1.23（0.36%）　　22歩でargmaxが10回反転

検証 03

根本原因 — 行動が効かない区間が最大化バイアスを溜める

4回の失敗はすべて同じ構造に由来していた。報酬の符号を変えても解決しなかったのは、問題が報酬設計ではなくQ関数の側にあったためである。

  1. TASC作動中は3つの行動がすべて同じ結果になる。環境が行動を上書きするため、力行・惰行・制動のどれを選んでも次の状態は変わらない。
  2. この状態で max を取ると、真値ではなくノイズの最大値を拾う。行動間に本来の差がないため、ネットワークの近似誤差がそのまま上振れとして残る。 行動間の差 3.7 → 1ステップあたり約1.8の過大評価
  3. 駅手前は0.1秒刻みで、割引がほとんど効かない。177ステップの連鎖にわたってバイアスが累積する。 γ = 0.9975 ^ 0.1 = 0.99975　　177 × 1.8 ≒ 320
  4. 本来0のはずのQ値が211まで膨張した。TASC区間の報酬はすべて0で、その後エピソードは終了する。したがって真のQ値は0である。 実測（試行04・cycle 1000）: TASC区間の maxQ 211.1
  5. 膨張が巡航側へ逆伝播し、Q値全体が押し上げられた。一方で行動の好みを表す差は元の大きさのままなので、相対的に潰れる。 Q値 198 → 500　　行動間の差は8〜10のまま＝全体の2%以下
  6. argmaxがノイズで入れ替わり、実質ランダムな行動選択になった。1秒ごとにランダムに力行/ブレーキを選べば、それはジグザグ運転そのものである。

なぜ「0点の罰」で修正されなかったのか

ジグザグに対して報酬NNは正しく0.0を出しており、罰は届いていた。しかしQ学習の更新式を見ると、その罰の大きさが問題になる。

Q(s,a) ← r + γ · max Q(s',·)
= (−0.5) + 0.99975 × 470
= 469.4　　← 罰の −0.5 は 470 の 0.1%

体重計が340kgを表示している状態で1.2kgの差を読み取ろうとするようなもので、目盛りの精度が足りない。正しい報酬が、壊れた伝達経路（Q関数）を通れなかったというのが4回の失敗に共通する構図である。

共通項は「行動がほとんど効かない長い連鎖」

試行01・04ではTASC区間（行動が完全に無効・177歩）、試行03ではクリープ区間（2〜8km/hで行動がほぼ無効・640歩）が、それぞれ同じ役割を果たしていた。TASC導入前は駅手前の制動でも行動が効いていたため、Q値は約65で安定していた。

引き継ぎの規則

  • 原則：DQNの軌跡が制動パターンに最初に到達した点で引き継ぐ。実車のTASCが作動する瞬間そのものにあたる。
  • ただし1つ手前から再現する：走行ログは巡航中1秒刻みのため、到達点は既にパターンを最大19m行き過ぎている可能性がある（69km/hで1秒＝19.2m）。制動は最大減速なので行き過ぎは回復できない。この配慮を入れる前は最大 +4.03m の誤差が残っていた。
  • パターンに達しない場合：DQNが早く減速しすぎたケースでは、最終減速の開始点まで遡り、その直前のノッチを延長してパターンまで走らせてから制動する。

教訓

この検証から得られたこと

  • エージェントが制御しない区間を強化学習の遷移に混ぜてはいけない。報酬をどう与えても（負・正・中立）歪みが生じた。混ぜないことが唯一の解だった。
  • 報酬設計の問題とQ関数の問題は切り分けて診断する。今回は報酬側が正しく罰していたにもかかわらず挙動が直らなかった。Q値の絶対値と行動間の差の比を見ることで初めて原因が判明した。
  • Q値のスケールは健全性の指標になる。本課題の理論上限は約200、正常時は約65である。数百を超えたら発散を疑うべきで、実際に失敗した試行ではいずれも膨張していた。
  • 自動制御装置は保証を与えるが、学習は保証しない。停止精度は「学習の成果」ではなく「上書きの帰結」であり、その切り分けを設計にも説明にも反映させる必要がある。
