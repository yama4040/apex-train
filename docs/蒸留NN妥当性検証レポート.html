要約

3件の指摘に対する検証結果

いずれの指摘も、着眼点はデータで裏付けられました。ただし「NNが手抜きをしている」という結論までは至らず、実際には別の要因（正則化項・データ量の偏り）で説明できました。

反証

評価NNは高頻度値（0.0 / 0.9 / 1.0）を出してLossを下げているだけではないか

ラベルが二峰性である点は事実。しかし最良の「手抜き」ベースラインに対し誤差が 2.8分の1、予測平均はラベルに単調追従しており、手抜きでは説明できません。

前提を訂正

モードNNは4分類ならaccuracyがもっと高いはず／Lossが高い気がする

実際は3クラス（4つ目は未実装）。accuracy は 0.983 と既に高水準で、表示Lossが高く見えたのはその23%がL2正則化項だったためです。

該当（ただし方針は現状維持）

モデルが適切なのかについても検証を

本質は3つの特徴量による閾値問題で、深層NNは能力過剰でした。実行時に担う唯一の役割では1行のルールがNNを上回ります（F1 0.954 対 0.919）。ただし研究方針としてモードNNは現状維持とします。

検証の前提

学習データの整理

検証の前に、意味論が古いデータを除外しました。target_speed_no_stop と forward_clear_remaining_time は先読み化の改修（7月31日）で算出方法が変わっており、それ以前に評価されたデータは同じ状況に別の値が付いています。

判別には「先行列車の観測遅延が正の行で、先行クリア残時間が 0 に潰れているか」を用いました。旧実装ではここが 0 になり、新実装では 15 秒以上を確保します。全ファイルが完全に旧・新へ分離し、中間の混在ファイルはありませんでした。

指摘 01 — 評価NN

高頻度値を出してLossを下げているだけではないか

評価NNについて、データ数の多い0.0や0.9とか1.0出しとけばLoss下がるとNNが学習していない？

0.0についてはデータ数が多いから分類器と0.0以外の値予測器に分けている。それなら、0.0でなく0.9や1.0を出しとけば正解と思っている気がする。

ただし、程度問題としては指摘が当たっている面もあります

希薄な中間値は苦手です。 頻出値（0.0 / 1.0）の MAE 0.054 に対し、希薄値（0.3 / 0.4 / 0.6 / 0.7）は 0.118 と約 2.2 倍。ただし最悪でもラベル刻み 0.1 の約1目盛以内に収まっています。

予測が中央へ圧縮されています。 低いラベルは高めに、高いラベルは低めに出る傾向（最悪はラベル 0.9 を 0.80 と予測）。回帰＋Huber損失の性質で、報酬のダイナミックレンジが約1割縮みます。改善するなら分類化・分位点回帰・サンプル重みの緩和度合いの見直しが候補です。

指摘 02 — モードNN

accuracyがもっと高いはず／Lossが高い気がする

分類モードNN、4分類問題ならaccuracyもう少し高くなるはず（Loss高い気がする）。データ量の偏り。モデルが適切なのかについても検証。

8月中間報告 指摘事項より

前提を訂正

学習対象は 4 分類ではなく、実質 3 クラスです

実装上の学習クラスは normal / delay_recovery / anti_mid_stop の 3 つです。4 つ目の spacing（運転間隔調整）は未実装でデータが 0 件のため学習対象外です。DQN へ渡す one-hot は 4 次元ですが、4 番目は常に 0 になります。

「Lossが高い」の正体 — 表示値の23%は正則化項

Keras が表示する損失には、交差エントロピーだけでなく kernel_regularizer による L2 ペナルティが含まれます。これを分離すると、予測誤差そのものは十分小さいことが分かりました。

モードNN（128–64–32、17,795 パラメータ）が、この課題に対して妥当な複雑さかを確かめるため、より単純な手法と比較しました。

深さ 4 の決定木が使った特徴量は forward_clear_remaining_time（重要度 0.57）、margin_signal_speed（0.21）、target_speed_no_stop（0.18）の 3 つでほぼ説明できます。つまり本質的には 3 変数の閾値問題であり、深層学習が本来必要とされる種類の課題ではありません。

実行時にモードNNが担う役割は1つだけ

モード判定をルールベース化した改修（設計メモ §19）以降、delay_recovery と normal の判別はルールが行います。したがって実行時にモードNNが担うのは anti_mid_stop（先行列車に塞がれているか）の判定のみです。その唯一の評価軸で比較すると、1 行のルールが NN を上回りました。

性格の違いがあります。NN は見逃しが 4 件と少なく安全側に倒れる一方、誤検出 61 件（不要な抑制）を伴います。ルールは誤検出ゼロですが見逃しが 33 件あります。

本研究での方針

ルール置換はパイプラインからNN 1つと再学習工程を取り除け、過去 2 回発生した「モードNNの再学習漏れ」という事故要因も断てる利点があります。一方で、見逃しの少なさ（安全側）は NN の長所です。

以上を踏まえ、モードNNは現状のまま研究を進める方針とします。本節の比較は、モデル選択の妥当性を確認した記録として残します。

付記

再学習が無言で失敗する不具合を修正

本検証のための再学習が 1 回目に失敗し、原因を突き止めて修正しました。学習自体は完走するのにモデルだけが更新されないという、気づきにくい失敗でした。

matplotlib の既定バックエンドが qtagg で、この環境では Qt の xcb プラグインを初期化できません。そのため plt.figure() が Python の例外ではなく SIGABRT でプロセスごと終了させます。学習スクリプトは学習曲線の描画をモデル保存より前に呼んでいたため、学習完了後・保存直前に落ちていました。

両学習スクリプトに非対話バックエンド（matplotlib.use('Agg')）を指定して解決し、以降は学習曲線とモデルの双方が正しく保存されることを確認しています。
