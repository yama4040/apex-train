報酬予測NNの最終構成

出力ヘッドの比較検証を経て採用した構成と、「NNは高頻度値を出してLossを下げているだけではないか」という指摘に対する実測での検証

要約

結論は2つ

構成

出力ヘッドは従来のスカラー回帰（Huber）を維持する

HL-Gaussian（ビンsoftmax＋ガウス目標）を実装して2回比較しましたが、有意に勝った項目はひとつもなく、上端（ラベル0.9〜1.0）で有意に劣りました。理論上の利点は本データでは実現しません。

反証

「高頻度値でLossを下げているだけ」ではない

指摘そのものを実装したベースラインに対し誤差は2.92分の1。さらに決定的なのは、過剰生産比と学習件数の順位相関が −0.855、つまりNNは「データの少ないラベルほど余計に出している」ことです。頻度への迎合とは逆向きの挙動です。

選定経緯

HL-Gaussianを実装して比較した結果

「回帰＋Huber損失では予測が中央へ圧縮される」という課題に対し、Imani & White (ICML 2018) の HL-Gaussian を実装しました。出力を値域ビンの softmax にし、教師をラベル中心の打ち切り正規分布に変換して交差エントロピーで学習する方式です。予備ビンを両端に置いて端の打ち切りバイアスも解消しています（最大ズレ 0.0369 → 0.0024）。

同一データ・同一分割・同一の幹で学習し、丸めの有無を揃えたうえで対応のあるブートストラップ（2,000 回）で比較しました。ラベルが 0.1 格子上にあるため丸めは無条件に有利に働き、揃えないと比較が歪むためです。

HL-Gaussianが上端で負ける理由

期待値読み出しの構造的な保守性です。ラベル 1.0 はデータの 25.6% を占める点質量ですが、期待値で 1.0 を出すにはビン確率をほぼ全て 1.0 側へ集める必要があり、0.95 に残った質量がそのまま予測を引き下げます。スカラー回帰は 1.0 を直接出力できるためこの不利がありません。ラベル0.9〜1.0だけでテストの 35.5% を占めるので、校正の傾きと分散比まで押し下げられました。

ゼロアトム統合（ゲートを単一ヘッドに統合する案）も不採用

ゲートを廃して単一 softmax に統合する構成も試しましたが、真値0.0のMAEが 0.017 → 0.041〜0.062 と 2.4〜3.6 倍に悪化しました。ゲート確率は実質的に二値（π<0.1 が 64.7%、π≥0.5 が 32.6%、中間はわずか 2.7%）で、統合による「閾値の不連続の除去」という利点はほとんど働きません。

指摘の検証

高頻度値を出してLossを下げているだけではないか

評価NNについて、データ数の多い0.0や0.9とか1.0出しとけばLoss下がるとNNが学習していない？

0.0についてはデータ数が多いから分類器と0.0以外の値予測器に分けている。それなら、0.0でなく0.9や1.0を出しとけば正解と思っている気がする。

8月中間報告 指摘事項より

ラベルが両端に偏っているのは事実です。0.0 が 32.2%、1.0 が 25.6% で、両端だけで 57.8%。中間値は各 1〜4% しかありません。「両端を出しておけば当たる」構造は実在します。以下、5つの角度から検証します。

根拠 4 — 過剰生産の向きが頻度と逆（最も決定的）

「余計に出している値」がどれかを、過剰生産比（予測件数 ÷ 真値件数）で調べました。頻度に迎合しているなら、学習件数の多いラベルほど過剰に出るはずです。

Spearman(学習件数, 過剰生産比) = −0.855

強い負の相関です。NNは「学習件数の少ないラベルほど余計に出している」ことになり、頻度への迎合とは正反対の挙動です。

実際、最も学習件数が少ないラベル 0.7（255 行）の過剰生産比は 7.98 倍。一方でラベル 1.0（7,727 行）は過少生産です。「0.9 や 1.0 を出しておけば正解と思っている」という想定とは真逆の結果でした。

頻度重心（0.454）への収縮係数 β も +0.146 と小さい値です。β=1 なら予測が完全に頻度重心へ潰れていることを意味しますが、実測はその 15% 程度しか引かれていません。

根拠 5 — 順序が正しく再現されている

  • ラベル別の予測平均が厳密に単調増加：0.018 → 0.220 → 0.297 → 0.402 → 0.464 → 0.553 → 0.602 → 0.705 → 0.762 → 0.794 → 0.905
  • Spearman ρ = 0.9213、Pearson r = 0.9175
  • 真値差 0.2 以上のペア（203,814 組）の順位一致率 94.61%

両端しか出していないなら、中間ラベルの予測平均は両端に張り付き、単調性は崩れます。実際にはラベルが 0.1 上がるごとに予測平均もきれいに上がっています。強化学習では報酬の絶対値より順序が効くため、この点は特に重要です。

結論：指摘は反証されました

5つの角度すべてで否定的な結果が出ました。とくに根拠4の ρ = −0.855 は決定的で、NNの過剰生産はデータ量の多い値ではなく少ない値に向いています。高頻度値でLossを下げているという説明は成立しません。

残る本当の問題

では、なぜ 0.6〜0.7 を過剰に出すのか

頻度が原因でないなら、最少データの 0.7 を 8 倍も出す理由は別にあります。原因はラベル側の矛盾です。

2026-08-13 の調査で、ほぼ同一の入力に高低両方のラベルが付いている領域が特定されました。「ノコギリ運転なら上限0点」という減点規則を LLM が CSV バッチによって適用したりしなかったりしており、適用率が 77.4%（19ファイル）と 16.6%（26ファイル）に二極化しています。同じ状況に 0.0 と 1.0 の両方が付けば、二乗誤差を最小にする予測はその条件付き平均、つまり 0.6〜0.7 になります。

これは損失関数やヘッドをどう変えても動きません。実際、HL-Gaussian でも過剰生産比の形はスカラー回帰とほぼ同一で、Balanced MSE も全指標で悪化しました。手法側で回避できる問題ではないことが 3 度の試行で確認されています。

次に効く一手

1. ノコギリ減点規則の適用揺れを解消して再ラベルする。これが 0.6〜0.7 への収束を生んでいる直接の原因です。

2. python analyze_reward_imbalance.py --noise-check で既約ノイズ（ベイズ誤差の目安）を測る。ラベルを直したとき balanced-MAE をどこまで下げられるかの上限が分かります。

3. ラベル整合後に HL-Gaussian を再評価する。今回は中央（0.3〜0.7）で −0.0038 と、あと一歩で有意に届く水準でした（上側CI +0.0002）。矛盾が消えれば結論が変わる可能性があります。
